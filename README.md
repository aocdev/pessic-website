# Pessic website

Landing page for [Pessic](../pessic), the desktop monthly budget app: what it does, how to get started,
screenshots, questions, and the installers. Plain HTML, CSS and JavaScript, with no frameworks,
external fonts or trackers. A small Python script (standard library only) builds the pages from
templates and the texts in `i18n/`.

```
src/index.html          page templates: HTML with {{key}} placeholders, no text
src/manual.html
i18n/ca.json            every text of the site, in Catalan (the default language)
index.html, manual.html generated by tools/build.py: do not edit them by hand
css/styles.css          styles; light and dark mode follow the system
js/main.js              download buttons, system detection, screen tabs, zoom, mobile menu
js/release.js           the published release: links and SHA-256 (written by tools/release.py)
js/downloads.js         download counts: a placeholder here, the real counts are written when deploying
assets/                 icon (from the app) and screenshots (WebP)
tools/build.py          builds the pages from src/ + i18n/ (+ the app's MANUAL.md)
tools/check.py          checks the built pages: tags, files, anchors
tools/release.py        points the downloads to a release and its checksums
tools/downloads.py      counts the installers' downloads from every GitHub release
tools/screenshots/      retakes the screenshots from the real app
```

## Preview

Open `index.html` in a browser, or serve the folder:

```bash
python3 -m http.server 8000      # then open http://localhost:8000
```

## Hosting: GitHub Pages

The site is published at **https://aocdev.github.io/pessic-website/** by `.github/workflows/pages.yml`:

- **Every push to `main`** checks the pages and deploys them. Only what the site needs is published:
  `index.html`, `manual.html`, `css/`, `js/`, `assets/` and the translation folders; never `src/`,
  `tools/` or the README.
- **Every Pessic release** updates the downloads by itself: the app's Installers workflow sends a
  `pessic-release` event, and this workflow runs `tools/release.py <version>`, commits
  `js/release.js` and deploys. **Actions > Pages > Run workflow** with a version does the same by hand.

- **Download counts**: every deploy runs `tools/downloads.py`, which adds up the downloads of the
  installers in every Pessic release (from GitHub's API) and writes them into the published
  `js/downloads.js`: a total under the download heading and a count on each system's card. A daily
  scheduled run keeps them fresh. Visitors' browsers never contact GitHub, and the counts are not
  committed (the repository keeps a placeholder with zeros, so a local preview shows no counts). GitHub
  counts every download, including bots and your own; `SHA256SUMS.txt` is not counted. GitHub pauses
  scheduled workflows after 60 days without activity in the repository; any push resumes them.

One-time setup:

1. In this repository: **Settings > Pages > Source: GitHub Actions**.
2. A token that lets the app's repository start this workflow: on GitHub, **Settings > Developer
   settings > Personal access tokens > Fine-grained tokens > Generate new token**, owner `aocdev`,
   only the repository `pessic-website`, permission **Contents: Read and write**.
3. In the app's repository (`aocdev/pessic`): **Settings > Secrets and variables > Actions > New
   repository secret**, name `WEBSITE_DISPATCH_TOKEN`, value the token. Without it, releases still
   work; the website is then updated with **Run workflow**.
4. If `main` gets branch protection, allow GitHub Actions to push to it (the workflow commits
   `js/release.js`).

To move to your own domain or another hosting later, upload the same files the workflow publishes
(the list above), or add the domain in **Settings > Pages > Custom domain**.

## Publishing the installers

The download buttons and their SHA-256 checksums come from `js/release.js`, written by
`tools/release.py` from the release's `SHA256SUMS.txt`. After the app's Installers workflow has
published a release (tag `v1.0.0`):

```bash
python3 tools/release.py 1.0.0                          # reads SHA256SUMS.txt from the GitHub release
python3 tools/release.py 1.0.0 --sums SHA256SUMS.txt     # or from a downloaded copy
python3 tools/release.py 1.0.0 --clear                   # back to "Aviat disponible"
```

With GitHub Pages this happens by itself on every release (see above). By hand: it links each button
to its file in the release (`Pessic-1.0.0.msi`, `Pessic-1.0.0-arm64.dmg`,
`Pessic-1.0.0-x64.dmg`, `pessic_1.0.0_amd64.deb`, `pessic-1.0.0-1.x86_64.rpm`) and writes its
SHA-256. Then upload the site again; no rebuild is needed, because `js/release.js` is not generated
from the templates.

- While a link is empty its button says "Aviat disponible", and the section explains that the
  installers are not published yet.
- With checksums, each card lists its files' SHA-256 with a copy button, and a "Comprova la
  descàrrega" box explains how to check a download on each system and links to `SHA256SUMS.txt`.
- Once the visitor's system has an installer, the main button at the top downloads it directly and the
  card for that system is highlighted.

## Texts, translations and the manual

The pages are generated. After changing a template in `src/`, a text in `i18n/`, or the app's
`MANUAL.md`, run:

```bash
python3 tools/build.py              # or: python3 tools/build.py path/to/pessic
```

- **Texts** live in `i18n/ca.json`, grouped by section (`hero.title`, `faq.bank.q`…). Values may contain
  simple inline HTML (`<strong>`, `<em>`, links). In the templates, `{{key}}` inserts a text,
  `{{@key}}` a text inside an attribute (`alt`, `aria-label`…), and `{{=name}}` a value from the build.
  The texts used by `js/main.js` are the `js.*` keys; the build embeds them in each page.
- **Adding a language**: copy `i18n/ca.json` to `i18n/<code>.json` (for example `es.json`), translate the
  values and run the build. The page is written to `<code>/index.html`, and a language switcher appears
  in the menu. Keys missing from a translation fall back to Catalan, with a warning.
- **The manual** comes from the app's `MANUAL.md`. For a translated manual, add `MANUAL.<code>.md` next to
  it; until then, that language links to the Catalan manual. Links like
  `manual.html#3-posa-ho-a-punt-15-minuts` keep GitHub-style anchors.
- The build stops with an error if a template or `js/main.js` asks for a key that `ca.json` does not
  have, or if `ca.json` has a key nothing uses.

## Updating the screenshots

All screenshots show **invented data**: the profile "Marta" from the app's test sample
(`pessic-db/src/test/resources/backup-sample.json`), with a few months, a reserve and two savings goals
added by `tools/screenshots/MakeDemo.java`. Never take screenshots of a real profile.

```bash
(cd ../pessic && mvn -q install -DskipTests)   # once, so the app's classes are built
tools/screenshots/take.sh
```

The script uses a temporary database (`PESSIC_DB`) and a fixed date (`PESSIC_TODAY`), so it never
touches your own Pessic data, and writes `assets/screens/*.webp`. A window opens for a few seconds
while it works.
